# WHOOP-style Age Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Body Age with a WHOOP-style Age (nine WHOOP metrics, WHOOP targets, years = 10 x ln HR, 6-month window, WHOOP's 30-day Pace) and rebuild the owner's history from his Health export without losing live mornings.

**Architecture:** A new pure module `whoop_age.py` scores day rows. Day rows gain logged-workout zone minutes and lean mass %, filled by the morning run, the back-fill and the import. The weekly report, the back-fill's weekly snapshots and the card switch to the new model; `healthspan*.py` is deleted. A helper command patches the new columns into the existing states from an import and recomputes the weekly history.

**Tech Stack:** Python 3 standard library, pytest.

**Spec:** `docs/superpowers/specs/2026-11-23-whoop-age-design.md`

## Global Constraints

- Standard library only; every input error is an `InputError` with file and line, never a guess.
- Years per metric = 10 x ln HR; overlap factor 0.70 on every metric except "Hours of sleep" and "Sleep consistency"; no caps.
- Window 182 days ending on the report date, plain mean; a metric with < 30 days of data counts 0 and is listed missing (VO2 max: >= 2 readings, latest within 120 days; lean mass: a value within 90 days).
- Pace = 1 + (total over 30 days - total over 182 days) / 0.5, clipped to [-1, 3]; withheld (None + reason) unless >= 21 of the last 30 days have sleep_min.
- Item names, in this order: "Hours of sleep", "Sleep consistency", "Steps", "Zones 1-3", "Zones 4-5", "Strength", "VO2 max", "Resting HR", "Lean body mass".
- Card wording: "WHOOP-style Age", and "an estimate from population research, not a medical test".

## Review Focus

- A new user with < 30 days: every metric missing, body_age == age, pace None with a reason (Task 1 test).
- Days with sleep times missing between nights: consistency skips nights with < 2 comparable prior nights (Task 1 test).
- An old state document without the new columns must still load (Task 2 test: read a fixture state lacking them).
- A workout with no minute heart rate on a worn day: zone minutes 0, not None; an unworn day: None (Task 2 test).
- The rebuild must never overwrite a value a live morning already stored (Task 5 test).
